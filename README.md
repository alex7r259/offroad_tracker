# Трекер внедорожных соревнований

Проект описывает систему **Offroad Tracker v1.0**: сеть GPS-трекеров на ESP32, E220 LoRa и GPS ATGM336H для контроля участников внедорожных соревнований. Система проектируется не как одиночный GPS-маяк, а как масштабируемая mesh-сеть для 3–50+ автомобилей.

## Цели v1.0

- Отслеживать координаты участников в реальном времени.
- Передавать SOS-сигналы с подтверждением базы.
- Использовать каждый трекер как ретранслятор для увеличения покрытия трассы.
- Поддерживать базовую веб-настройку без внешней инфраструктуры.
- Масштабироваться до десятков узлов без изменения протокола.

## Общая архитектура

```text
                 БАЗА

        ESP32 + E220 + Web UI
                 ↑
                 │
        LoRa Mesh Network
                 │
 ┌───────┬───────┴───────┬───────┐
 │       │               │       │
Авто1  Авто2          Авто3   АвтоN

ESP32 + GPS + E220 + SOS
```

Каждый автомобильный узел одновременно выполняет роли:

- GPS-трекера;
- LoRa-ретранслятора;
- источника телеметрии;
- SOS-терминала участника.

База принимает пакеты mesh-сети, ведет таблицу участников, отображает тревоги и отправляет подтверждения SOS.


## Прошивка

В репозитории добавлена стартовая прошивка ESP32 под Arduino/PlatformIO. Она реализует базовый набор v1.0: чтение GPS, измерение батареи, SOS-кнопку, LoRa mesh-пакеты через E220, повтор SOS до `ACK SOS`, таблицу узлов и Web UI в режиме точки доступа.

### Сборка и загрузка

```bash
pio run
pio run --target upload
pio device monitor
```

### Распиновка прошивки

| Модуль | Сигнал модуля | GPIO ESP32 | Комментарий |
| --- | --- | ---: | --- |
| E220-400T22D | M0 | 32 | Режим работы радиомодуля |
| E220-400T22D | M1 | 33 | Режим работы радиомодуля |
| E220-400T22D | RXD | 14 | ESP32 TX -> RXD E220 |
| E220-400T22D | TXD | 27 | ESP32 RX <- TXD E220 |
| E220-400T22D | AUX | 15 | Готовность модуля |
| ATGM336H | TX | 16 | ESP32 RX <- TX GPS |
| ATGM336H | RX | 17 | ESP32 TX -> RX GPS |
| Кнопка SOS | GPIO25 -> GND | 25 | Используется `INPUT_PULLUP` |
| Батарея 18650 | Делитель 47 кОм / 22 кОм | 34 | ADC с коэффициентом делителя |

### Первый запуск

После прошивки устройство поднимает Wi-Fi точку доступа `Tracker-<ID>`. В Web UI доступны главная страница, настройки ID/позывного/интервала/TTL, переключение SOS и таблица известных mesh-узлов.

### Уточнения реализации

- GPS-время в пакете хранится как `HHMMSS`; дата не передается в коротком радиопакете.
- Высота передается в дециметрах полем `int32_t`, чтобы избежать переполнения выше 3276,7 м.
- Radio RX синхронизируется по `PACKET_MAGIC`, поэтому потерянный байт или шум не ломают прием навсегда.
- Ретрансляция выполняется через очередь и отдельную задачу `relay_tx`, а не с задержкой внутри RX-задачи.
- `ACK SOS` не ретранслируется, чтобы не создавать лишний трафик подтверждений.
- Старые узлы удаляются из таблицы после 30 минут без связи.
- `sequenceCounter` защищен критической секцией, а `sosSequence` обновляется под `stateMutex`, чтобы параллельные задачи не создавали рассинхрон.
- Переполнение `relayQueue` учитывается счетчиком `relayDrops`, который выводится на главной странице Web UI.
- Link Quality рассчитывается по принятым и пропущенным sequence-пакетам, сбрасывается при обнаружении перезапуска узла и выводится в таблице узлов.
- В пакет добавлены `uptimeSeconds` и `role`, чтобы база видела перезагрузки и тип участника: `0=participant`, `1=organizer`, `2=ambulance`, `3=evacuation`, `4=base`.
- Для снижения шторма при 30–50 участниках ретрансляция разрешена только при слабом RSSI или малом числе hops.
- Если ваш E220 не добавляет RSSI-байт в текущем режиме, установите `E220_RSSI_BYTE_ENABLED = false` в `include/tracker_config.h`. Значения RSSI нужно откалибровать на дистанциях 1 м, 10 м, 100 м и 500 м перед соревнованием.
- GPS читается только в `gpsTask`, остальные задачи используют защищенный `GpsSnapshot`, чтобы не читать `TinyGPSPlus` из разных потоков.
- `ACK SOS` ставится в отдельную `ackQueue` и отправляется задачей `ack_tx`, поэтому Radio RX не блокируется на передаче ACK.
- UART RX-буфер E220 увеличен до 4096 байт, а Wi-Fi AP защищен паролем `tracker<ID>`.
- SOS-состояние сохраняется в NVS и восстанавливается после перезагрузки.
- Пакеты с `TTL <= 1` больше не ретранслируются, чтобы не занимать эфир последним бесполезным hop.
- При старте проверяется создание mutex/queue ресурсов FreeRTOS; при ошибке устройство пишет сообщение в Serial и перезагружается.
- В таблицу узлов добавлена строка `SELF` с текущими координатами, батареей, ролью и uptime устройства.
- Интервал обычной передачи позиции получает случайный jitter ±10%, а перед отправкой используется ожидание `AUX` как простая проверка готовности радиоканала.

## Аппаратная часть трекера

| Компонент | Назначение |
| --- | --- |
| ESP32 | Основной контроллер, Wi-Fi AP, Web UI, таблица узлов, планировщик задач |
| E220-400T22D | LoRa-радиомодуль 433 МГц для mesh-сети |
| ATGM336H | GPS-приемник |
| Кнопка SOS на GPIO25 | Ручное включение и отключение тревоги |
| Делитель 47 кОм / 22 кОм на GPIO34 | Измерение напряжения батареи |

### Радионастройки по умолчанию

- Частота: `433.920 МГц`.
- Мощность: `22 dBm`.
- UART: `9600 бод`.
- Air Data Rate: `2.4 kbps`.
- RSSI: включен.

Такие настройки выбраны как стартовая конфигурация для максимальной дальности. После полевых испытаний интервал передачи, мощность и параметры ретрансляции должны уточняться по RSSI и фактической загрузке эфира.

### GPS-данные

Трекер считывает из ATGM336H:

- широту;
- долготу;
- высоту;
- скорость;
- курс;
- GPS-время;
- количество спутников;
- статус fix.

### Логика SOS-кнопки

- Короткое нажатие включает SOS.
- Повторное короткое нажатие отключает SOS локально.
- При активном SOS пакет передается многократно до получения `ACK SOS` от базы или ручного отключения.

## Mesh-сеть

Каждый узел:

1. Передает собственную позицию.
2. Принимает пакеты других узлов.
3. Обновляет локальную таблицу узлов.
4. Ретранслирует новые пакеты с уменьшением TTL.
5. Игнорирует уже виденные пакеты по ключу `node_id:sequence`.

### TTL

| Тип пакета | TTL по умолчанию | Причина |
| --- | ---: | --- |
| `POSITION` | 3 | Ограничить загрузку эфира обычной телеметрией |
| `SOS` | 5 | Повысить шанс доставки тревоги до базы |

### Защита от дублей

Каждый пакет содержит:

- `node_id` — идентификатор участника или устройства;
- `sequence` — монотонный номер пакета от конкретного узла.

Пример ключей дублей:

```text
17:1001
17:1002
17:1003
```

Если ключ уже есть в кэше принятых пакетов, пакет не ретранслируется повторно.

## Типы пакетов

### POSITION

Основной пакет телеметрии. Содержит:

- ID узла;
- GPS-время;
- координаты;
- скорость;
- напряжение или процент батареи;
- количество спутников;
- флаги состояния;
- TTL;
- счетчик sequence.

### SOS

Тревожный пакет. Использует ту же базовую структуру, что `POSITION`, но содержит активный SOS-флаг и повышенный TTL. Передается повторно с коротким интервалом до подтверждения базы.

### ACK SOS

Подтверждение базы о получении SOS. После получения трекер прекращает автоматическую повторную передачу SOS, но оставляет локальный статус тревоги до ручного сброса или явного правила приложения.

### PING

Служебный пакет для диагностики сети, проверки дальности и контроля доступности узлов.

## Таблица узлов

Каждый трекер и база хранят до 50 записей `NodeInfo`:

```cpp
struct NodeInfo {
  uint16_t id;
  double lat;
  double lon;
  float speed;
  uint8_t battery;
  uint8_t satellites;
  uint32_t lastSeen;
  int16_t rssi;
  uint8_t hops;
  uint16_t flags;
};
```

Таблица используется для локального отображения, ретрансляции, диагностики и будущей карты.

| --- | --- | --- |
| GPS Task | 10 Гц | Чтение и парсинг GPS |

## База

Базовая станция использует:

- ESP32;
- E220;
- Wi-Fi;
- антенну 5–8 dBi;
- мачту 8–10 м.

### Интерфейс базы

Таблица участников содержит:

- ID;
- позывной;
- координаты;
- скорость;
- батарею;
- RSSI;
- hops;
- время последней связи.

### Обработка SOS

При получении SOS база должна:

1. Подсветить строку участника красным.
2. Включить звуковой сигнал.
3. Показать всплывающее окно.
4. Отобразить участника на карте.
5. Отправить `ACK SOS` обратно в mesh-сеть.

## Логирование

ESP32 хранит последние 1000 событий в кольцевом буфере.

Типы событий v1.0:

- `GPS LOST`;
- `SOS`;
- `NODE ONLINE`;
- `NODE OFFLINE`;
- `LOW BATTERY`.

## План внедрения

### Этап 1: Минимальная рабочая система

- 3 трекера.
- 1 база.
- Передача координат.
- SOS и `ACK SOS`.
- Ретрансляция.
- Веб-настройка.

### Этап 2: Полевые испытания

- Испытания в лесу.
- Замер RSSI.
- Подбор интервала передачи.
- Проверка TTL и дублей.
- Оценка пропускной способности сети.

### Этап 3: Масштабирование

- Проверка работы на 30–50 автомобилях.
- Настройка интервалов по классам участников.
- Добавление карты и улучшенной диагностики.
